# 実装の検証記録

2026-10-02 / Windows / Orpheus 0.1.0

## 実行して確認したもの

- 原スキーマ3件を変更せず、架空の契約例を検証。
- Pythonテスト34件、描画プリセットのNodeテスト2件、TypeScript型検査。
- パストラバーサル、重複ID、音源ハッシュ変更、画像欠落・ハッシュ変更、シーンの隙間、未知プリセット、未確認の補間時刻を拒否。
- 歌詞境界のフレーム丸め、実際の歌唱重複の拒否、場面をまたぐ字幕。
- 同期結果を再搬入しても手修正を保持。歌詞テキストが変わった修正を未解決として残す。
- 二重起動防止、失敗した描画だけの再開、出力改変時のキャッシュ無効化。
- 外部アダプターへの引数をシェル展開せず渡すこと。
- Qwen出力の行対応：繰り返しを順序通りに処理。不一致や行をまたぐトークンで時刻を捏造しないこと。

## 実際に描画した動画

6秒・1920×1080・30fps・180フレーム、H.264/AAC、48kHzステレオ。
テスト用の合成音、幾何学画像2枚、架空の日本語歌詞2行を使用しました。
slow_push、pan_right、12フレームのcrossfadeを含み、3秒の場面切替をまたぐ字幕を確認しました。

初回描画の後、画像1枚のピクセルと歌詞の開始時刻（0.75秒→0.9秒）を変更し、再描画しました。
過去のrunは保持され、新しいrunに変更後の素材・時刻を保存しました。resumeでは同一runを再利用しました。

各動画で全フレームの復号、フレーム数、解像度、fps、映像・音声尺、ステレオを検査しました。
元PCMと圧縮後PCMのゼロ遅延相関、250msごとの音量比較を行い、不意の無音を検出しませんでした。
検証JSONに実測値と許容差を記録しています。

## 音解析

合成パルス音をlibrosaへ入力し、11個の拍候補と約117.45 BPMの推定値を得ました。
これは120 BPMで作ったテスト信号への推定結果であり、実曲での精度評価ではありません。
解析後も手修正した0.9秒の歌詞開始時刻が保持されることを確認しました。
numba 0.68.0はこのWindows環境でDLL読込に失敗したため、動作確認できた0.63.1とllvmlite 0.46.0を固定しました。
