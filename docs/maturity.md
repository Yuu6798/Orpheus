## 状態の意味

| `maturity` | 表示 | 意味 |
|---|---|---|
| `stable` | 本体・安定契約 | 既存の本体として扱う範囲。契約に沿う動作と互換性を維持する。実曲・実素材での確認範囲は別に読む |
| `verified` | 実制作検証済み | 現在の実装について、記載した実素材・操作・環境の範囲で照合記録がある。設定形式は版付き拡張のままでよい |
| `experimental` | 実験的 | 実素材での実装照合、推定の有効性、または工程全体の確認などに未解決の項目がある。理由と次に確認する条件を読む |
| `external` | 外部実装 | 結果が利用者の外部プログラムに依存する入口。個別の接続確認は、その外部実装の範囲に限る |

`verified` は、あらゆる素材への適用、作品としての採用、推定値の正しさ、外部実行環境の存在を保証しない。
`technical_pass`・RunRecord の状態・人の `accepted` / `adopted` は、これまでどおり別の記録である。
既存の `stable` を、今回初めて実制作で検証した機能として数えない。

設定が `contracts/` の外にあることだけで、一律に実験的とはしない。fx・dance・model3d の設定形式は、それぞれの場所で版を管理する。
本体の `contracts/` の内容と配置は、この見直しでは変更しない。正式契約への変更は引き続きユーザーの判断に従う。

## 確認方法

```sh
uv run orpheus capabilities --maturity verified
uv run orpheus show mv.deliver.join
uv run orpheus show model3d.mesh.smooth_part_normals
uv run orpheus workflows --maturity experimental
uv run orpheus validate
```

カタログの `maturity_assessment` には、確認日、見直しの根拠、対象範囲、資料の場所、限界、次の昇格条件、次に見直す契機を載せる。
正典は [`maturity_assessments.json`](../src/orpheus_catalog/maturity_assessments.json)。コマンド・3D 操作・workflow の **完全な ID** で照合する。
同じグループの別の操作や、新しく追加した操作には昇格を引き継がせない。導入されていない optional component は、
`availability` にその理由を残し、過去の確認状況とは分ける。

コマンドの一部のオプションだけを実素材で確認している場合は、その範囲を `scope` と `limitations` に書く。
例えば字幕の SRT・WebVTT・概要欄の照合から、LRC の全入力経路や歌詞時刻の正確さを確認済みとはしない。
道具を移植して数値が一致しても、音の拍や異常検出のしきい値の有効性まで評価したことにはならない。

## 昇格と見直しの条件

### 実験的から実制作検証済みへ

1. 対象とする入力・操作・環境・出力を決め、**Orpheus の当該実装**を実素材で通す。元の試作だけの実績や合成素材だけの成功は区別する。
2. 元の制作手順・凍結した基準・期待する観測と照合し、一致した範囲、差の大きさと理由、未確認を記録する。
3. その処理を維持する回帰テストを確認し、根拠の資料・制約・次の条件を同じ変更で更新する。推定器は目的に沿った誤検出・見落とし等の確認も必要とする。
4. workflow は、必要な工程の接続を含めて確認する。部品ごとの実績から、全工程の成立を推測しない。

### 実制作検証済みから安定契約へ

対応する入力と環境、設定・出力の版、既存設定の互換性、変更時の移行方法を固定する。
記録した実素材の範囲と回帰テストを保ち、既知の問題がその保証範囲に影響しないことを確認する。
`contracts/` を変更する必要がある場合は、その具体的な差分を判断対象にする。ディレクトリを移すだけでは昇格しない。

### 次に見直すとき

次の実制作の完了時、対象操作の挙動を変える PR、次回リリース前のうち、最初に来た時点で見直す。
変更した処理が従来の照合を保つか確認できないときは、対象範囲を狭めるか実験的へ戻し、理由を残す。
期限の経過やテスト数だけで自動昇格させない。各操作の残条件は、下の一覧とカタログから読む。
