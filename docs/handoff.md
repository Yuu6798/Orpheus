# handoff（届いた絵の機械的な検査・実験的）

絵の描き直しを別の担当（画像を生成する別のエージェントや、人）に頼んだとき、届いた絵を受け取る前に機械で確かめる道具。

- **採点器ではない**: 「変えてよい範囲」の外が元の絵と同じか、大きさが同じか、だけを見る。絵の良し悪し・頼んだ通りに描けたか・作品としての採用は判定しない。
- **決まりとの関係**: AGENTS.md の「生成物の開発中は測定器・検証器の機能を足さない」の例外として、2026-11-16 にユーザーが認めた（受け渡しの絵の検査器）。
  例外はこの `mv handoff` の範囲だけ。
- **なぜ**: リポジトリ外の 2 作目の VRM のダンスで、表情の差分（微笑み・閉じ目）の顔の絵を別の担当に頼んだ。差分の絵の「変えてよい範囲」（目と眉のまわり、
  口のまわり）の外が少しでも変わっていると、絵を切り替えたときに顔全体がちらつく。届いた絵を検査し、範囲の外を元の絵に戻してから使った。
- 頼むときは、元の絵・変えてよい範囲（元の絵の画素の箱）・見本を渡し、受け取ったらこの検査をかける（小さな線の手直しは頼み直さず、画像の処理で行うと早い）。

## 1. 届いた絵を検査する

```sh
uv run mv handoff check 元の絵.png 届いた絵.png --region 390,555,870,700 --region 520,790,736,890 --restore 戻した絵.png
```

- 元の絵と届いた絵を 8 ビットの RGB で読み（アルファは捨てる）、画素ごとの差（3 色の差の絶対値の最大。0〜255）を測る。依存は numpy と Pillow だけ。
- `--region x0,y0,x1,y1`: 変えてよい範囲（くり返し可。元の絵の画素。右と下は含まない）。1 つ以上要る。
  `--regions-width W` を渡すと、幅 W の絵で書いた範囲として、元の絵の幅に合わせて伸ばす（頼んだときの絵と大きさが違うとき）。
- 大きさ: 届いた絵の大きさが元と違えば `fail`（測らない）。`--allow-resize` なら、届いた絵を元の大きさへ面積の平均で縮めて比べ、`warn`（位置が
  合っている前提。ずれていれば、範囲の外の差が大きく出る）。
- 範囲の外: 差が `--tolerance`（既定 8）を超える画素の数が `--max-changed`（既定 0）を超えたら `fail`。差の最大と平均、差が 24 を超える画素を囲む箱
  （範囲を書いた座標）も出す。PNG の保存のしかたの違いで 1〜2 の差が出ることがあるので、`--tolerance` は 0 にしない。
- 範囲の中: 差が `--tolerance` を超える画素が 1 つも無ければ `warn`（頼んだ所が変わっていない。取り違えた絵かもしれない）。
- `--restore OUT.png`: 範囲の外を元の絵に戻した絵を書く（PNG だけ。JPEG などの非可逆の書き出しは、戻した範囲の外の画素まで変えて、
  切り替えたときのちらつきを戻してしまうので、ほかの拡張子は検査の前に止める）。範囲の縁は `--feather`（既定 12。範囲を書いた座標の画素）でなめらかにつなぐ（範囲を
  `--feather` だけ内側へ縮めてから、σ `--feather` ÷ 2 でぼかす。範囲の外には一切にじまない）。合否に関係なく書く（大きさが違い、`--allow-resize`
  が無いときは書けない）。戻した絵は、その後の工程（`model3d` の `texture.project_reference` で頭の色の絵に写すなど）の入力にする。
- 出力（`--out`。既定は届いた絵の隣の `<届いた絵の名前>_handoff_report/`）は `handoff_report.json`（`handoff-check/0.1`）: 2 つの絵の名前と sha256、
  大きさ、設定、範囲の外と中の数、戻した絵の名前と sha256、`status`（`pass`・`warn`・`fail`）と理由。同じ入力と設定なら同じ報告（時刻や絶対パスは
  書かない）。標準出力には要約。
- 終了コードは `fail` のとき 1（`warn` は 0）。

## 確かめたこと

- CI では、合成の絵で、範囲の中だけの変化（`pass`）・範囲の外の変化（`fail` と箱。`--max-changed` まで許す）・範囲の座標の伸ばし・大きさの違い
  （`fail`、`--allow-resize` で `warn`）・範囲の中が変わらない（`warn`）・戻した絵（範囲の外は元の絵、範囲の芯は届いた絵）・終了コード、
  縮める処理とぼかしが OpenCV（`erode`・`GaussianBlur`）と同じ値になること（OpenCV があるとき）を確かめた。
- 2026-11-17 に、リポジトリ外の 2 作目の VRM のダンスの台本（表情の差分の絵を検査して範囲の外を戻す台本。OpenCV）と、届いた 2 枚（微笑み・閉じ目。
  1254 画素）で比べた（実測）。範囲の外と中の数（差が 8 を超える画素、差の最大と平均、箱）が台本と同じ。戻した絵は、台本をかけ直したものとも、
  制作で使った絵とも画素まで同じ。2 枚とも `pass`（範囲の外の差の最大は 1 と 0）。

## 限界

- 位置合わせはしない（届いた絵が元の絵と同じ構図で描かれている前提）。範囲の外の差が出たら、ずれか描き足しかは絵で見る。
- 絵の中身（頼んだ表情になっているか、線の太さなど）は判定しない。
- 8 ビットの RGB だけ（16 ビットの PNG・アルファは見ない）。
