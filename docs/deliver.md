# 受け渡しの書き出し（`mv deliver`）

描いた区間の動画をつなぎ、音を付けて元データ（master）にする（実験的）。cv2 を使わないので、fx の extra が無くても動く。
映像は再エンコードしない。描画・送信・公開はしない。

```sh
uv run mv deliver join render_r3 --out render_r3/song_master.mp4 \
    --audio build/src/song.wav --audio-start 132.7 --fade-out 0.5          # seg_<最初>_<終わり>.mp4 のフォルダから
uv run mv deliver join a.mp4 b.mp4 c.mp4 --out master.mp4                  # 区間をこの順に。音なし
```

## つなぎ方（`mv deliver join`）

1. **区間**: 渡した順につなぐ。フォルダを 1 つ渡すと、その中の `seg_*.mp4` を名前の順に使う。
   - 名前が `seg_<最初のコマ>_<終わりのコマ>.mp4`（区間を並べて描くときの名前）なら、区間がすき間なく続くことと、区間ごとのコマ数
     （終わり − 最初）を確かめる。名前が違う区間が混ざっていれば、この確かめは省き、全体のコマ数だけを確かめる。
   - どの区間も、寸法・fps・映像の符号化（codec と画素の形式）がそろっていること。再エンコードせずにつなぐため。
2. **映像**: ffmpeg の concat で、映像を再エンコードせずにつなぐ（`-c copy`）。つないだコマ数が区間の合計と同じかを確かめる。
3. **音**（`--audio` を渡したとき）:
   - `--audio-start` 秒から、映像の長さを切り出す。映像の長さは、区間ごとのパケットの時刻（time base・pts・長さ）から正確に出す。
     ffmpeg が表示する fps は 23.98 のように丸めてあり、コマ数 / fps では 24000/1001 fps の長さがずれるため（整数の fps なら同じ値）。
   - 頭（`--fade-in`、既定 0.02 秒）と終わり（`--fade-out`、既定 0.25 秒）にフェードを掛ける（fx の書き出しと同じ既定値）。
     フェードの長さ（合わせて映像より短いこと）は、音を付けるときだけ確かめる。
   - AAC 192k・48kHz にする。
4. **元データ**: 映像と音を `-c copy` で合わせ、映像の長さで切り、faststart（先頭に目次）で書く。
   - 既に同じ名前のファイルがあって中身が違えば、`--force` を付けない限り書かない。同じ中身なら `unchanged`。
   - `--out` が入力（区間の動画・`--audio`）と同じファイルなら、`--force` でも書かない（置き換えると入力が消えるため）。
   - 作業のファイルは出力の隣の一時フォルダに作り、終わったら消す。
5. **記録** `<元データの名前>.deliver.json`（`deliver-join/0.1`、`contracts/` の外）:
   - 区間（パス・sha256・コマ数・名前の区間）と、音（パス・sha256・切り出し・フェード）。
   - 使った ffmpeg（パス・版・sha256）と、ffmpeg のコマンド。
   - 元データの bytes と sha256。
   - 構造検査（寸法・fps・コマ数・音の尺。`technical_pass`。作品の採否ではない）。

色のタグは区間のまま（つなぐだけで変えない）。fx・dance で描いた区間なら BT.709 のまま。

## 同じバイト列になる条件

手順と ffmpeg の引数は、実制作の仕上げ（片をつないで音を付ける）と同じ。ただし ffmpeg の版が違うと、音の符号化と入れ物の書き方が変わり、
バイト列は変わる。同じ ffmpeg は `ORPHEUS_FFMPEG` で選べる（既定は PATH の ffmpeg、無ければ imageio-ffmpeg 同梱版）。記録の ffmpeg の
sha256 で、同じ ffmpeg だったかを確かめられる。

## 共通の書き出し（`encode.py`）

fx・dance・overlay・timeline・clips の BT.709 の書き出し（`write_video`・`ffmpeg_command`。libx264 / bt709 / tv / yuv420p / AAC）は、
cv2 を使わない `src/mv_pipeline/encode.py` に置いた（`fx/render.py` からも同じ名前で使える）。fx の extra の要らない道具も、同じ書式で書ける。
fx の指紋（`fx.fingerprint`）はこのファイルも含むので、書き出しを変えれば fx の run は描き直しになる。

## 実制作との比較

- 実制作の仕上げの手順（ffmpeg の引数をそのまま写したもの）と、合成の 3 区間（18 コマ）と合成の音で、元データが同じバイト列だった（`tests/test_deliver.py`）。
- 実際の 2 本（縦の Shorts。どちらも 6 区間）でも、実制作が描いた区間と同じ音源から `mv deliver join` で作り直した。どちらも、実制作の記録の
  sha256 とバイト単位で同じだった。

| 本 | コマ | 音の切り出し | フェード | 元データ |
|---|---|---|---|---|
| 1 本目 | 747（24.9 秒） | 132.7 秒から | 0.02 / 0.5 秒 | 63,332,051 バイト、同じ |
| 2 本目 | 837（27.9 秒） | 189.3 秒から | 0.02 / 0.5 秒 | 78,586,291 バイト、同じ |

確認用の小さい版（2 パス）と、受け渡しのための分割は、まだ無い（次の段階で足す）。
