# inspect（生成動画の検品・実験的）

生成した動画（i2v のカット・緑背景のダンス素材・3D の描画など）から、異常の候補を**コマ番号と秒で**見つけて形状・動作・衣装・連続性に分ける道具。設定画と配色を照合し、見つけた所を**直す場所**（元動画のコマ・dance の spec の clip と出力の秒・生成の素性）に結び付ける。

- **採点器ではない**: 数値と根拠を出すだけで、合否・採否・好みは決めない。**検出が無いことは合格ではない**（採用は人。`mv dance accept` などの人の判定）。
- **決まりとの関係**: AGENTS.md の「生成物の開発中は測定器・検証器の機能を足さない」の例外として、2026-11-07 にユーザーが依頼した（BytePlus の生成動画の品質評価から取り入れる機能の一覧）。例外はこの `mv inspect` の範囲だけ。
- **推定を実測扱いしない**: 数値は動画から測った値（`evidence: measured`）。それを異常と読むかは人が見て決めるので、出来事はどれも `status: review`（要確認）。VLM の指摘は推定（`estimated`）として分けて残す。
- **しきい値はどれも仮の値**: 合成素材（`mv inspect demo`）で決めた。実素材では 2026-11-07 に生成 AI の動画 4 本と Blender の描画で通しただけで（下の「実素材での確かめ」）、変えたのは数える塊の大きさ（いちばん大きい塊の 2% → 1%。Blender の描画で離れた拳ほどの塊を見落としたため）だけ。実作品で `metrics/<クリップ>.csv` を見て直す。
- **送信しない**: Orpheus はネットワークを呼ばない。VLM はユーザーが CLI で明示した外部プログラムだけを呼び、素材を外へ送る設定は `--allow-send` が無いと動かさない。
- **自動の再生成はしない**: 修正計画（`fix_plan.json`）に、生成し直す区間・前後のコマの画像・生成の素性・手当ての候補を書くだけ。

## 取り入れた機能

| 機能（ユーザーの表） | Orpheus での形 | 優先度 | 状態 |
|---|---|---|---|
| 異常箇所の特定 | 出来事ごとに元動画のコマ番号 `[開始, 終了)`・秒・山のコマ・画面の中の場所（正規化の箱）と、前・山・後のコマを並べた静止画 | 高 | 実装 |
| 異常の分類 | 形状・動作・衣装・連続性。規則で主な分類を 1 つ決め、同じ所のほかの分類も残す | 高 | 実装 |
| 参照画像との照合 | 設定画の主な色と、コマの人物の色の重なり・欠けた色・設定画に無い色 | 高 | 実装（配色だけ。形・顔の照合は VLM に任せる） |
| 時系列の一貫性検査 | 前のコマとの差の急変と戻り、明滅、止まったコマ、水増しの周期、人物の消失 | 中 | 実装 |
| ニューラル品質評価 | VLM への依頼の束と外部プログラムの呼び出し。返答は推定として出来事に添える | 中 | 実装（代役で確かめ、Claude のアダプタを実際の API で 3 回通した。下の「実素材での確かめ」） |
| 自動再生成 | 修正計画: 直す区間・前後のコマ（始点・終点の画）・素性・手当ての候補 | 将来 | 計画を書くだけ（実行しない） |

**検査の結果を直す場所に結び付ける**のが中心の設計。出来事には必ず `target`（直す場所）と `actions`（手当ての候補）が付き、修正計画は出来事をクリップごとの「生成し直す区間」にまとめる。

## 5 分で試す（合成素材）

```sh
uv sync --locked --extra analysis --extra fx                  # cv2 が要る（fx extra）
uv run mv inspect demo projects/inspectdemo                   # sheet.png（設定画）・clip.mp4（異常を 7 か所に入れた緑背景の人物）・inspect.json・expected.json
uv run mv inspect check projects/inspectdemo/inspect.json     # → projects/inspectdemo/inspect_report/
```

デモの人物は頭・髪・深紅の上着・スカート・脚の図形で、左右に揺れて腕を振る。入れた異常（24 fps）は、小刻みな揺れ（コマ 8〜19・動作）、1 コマの明るさの明滅（24・連続性）、1 コマだけ別の画（30・連続性）、同じ絵が 4 コマ（40〜43・連続性）、腕から離れた塊（50〜52・形状）、上着が青になる（60〜74・衣装）、横へ飛んで戻る（84〜85・動作）。どれも入れたコマと分類で見つかり、ほかの所では何も出ない（`tests/test_inspect.py`）。異常の無い素材・dance のデモの棒人間・fx のデモでも何も出ないことを確かめた。**合成素材で働くことは、実作品で見落としや誤検出が少ないことを保証しない。**

## 実素材での確かめ（2026-11-07）

素材はリポジトリに入れていない。数値は 1 回通した結果で、見落としと誤検出の率ではない。

- **dance_spec**: 生成 AI の緑背景のダンス動画 2 本（768×1168。24 fps 7.4 秒と 30 fps 2.9 秒）を、デモの夜のステージに `mv dance render` で合成した（10 秒 240 コマ。1 本は 2 か所で使い、つなぎは cut と blend 3 コマ。`technical_pass`）。同じ spec を、暗い背景のキャラシートの三面図を `box` で 3 体（front・side・back）に切り出した設定画と一緒に検品した（258 コマ・約 16 秒）。見たコマは spec で出る元のコマだけ（24 fps の素材は 178 コマ中 0〜169）。
- **見つけたもの**: 形状（輪郭の急変）3 件。2 件はコマの絵の崩れ（前後の姿勢が混ざって手が二重になったコマ、速い振りで袖ごと腕が流れたコマ）で、1 件は速い腕の振りそのもの（静止画では崩れは見えない。要確認として人が外す類）。直す場所は spec の clip（`/performer/clips/0` と、同じ素材を後で使う `/performer/clips/2`）と出力の秒に結び付き、手で計算した値と合った。修正計画は 3 区間で、前後のコマの画像と素性が入った。
- **直したこと**: 背中を向いて回るコマで、正面の設定画の薄い色が欠けたとする衣装の出来事が 1 件出た（背面の設定画と比べると欠けは無い）。同じ衣装の向き違いは重なりの差が 0.01〜0.04 しかなく、比べる設定画がコマごとに入れ替わっていた → そのコマをいちばんよく説明する設定画と比べるようにした（上の `reference[]`）。あわせて、同じファイルの設定画を向きの名前で書き分け、切り抜きを `references/` に残し、数値の出来事に添えた VLM の指摘の文を表に出すようにした。
- **i2v**（緑背景でない、`foreground: "none"`）: 3 本つないだプレビュー（640×360・16 fps・15 秒）は、つなぎ目の 2 か所（コマ 81・162）を画の切り替わりとして見つけ、ほかは無し。始点と終点を指定した i2v 1 本（1280×720・24 fps・5 秒）は何も出なかった。
- **合成後の出力**: `dance.mp4` を `clips` で見ると、緑が無いので形状・衣装は見ていない（未実施と出る）。崩れは出ず、つなぎ目も出なかった（推測: 人物が画面の一部で、つなぎ目のカメラの動きがなだらかなため）。生成の崩れは、元の動画を `dance_spec` で見て見つける。
- **VLM**: 依頼の束（15 コマ・設定画 3 枚）と、Claude のアダプタの `--dry-run`（3 バッチ）まで。**送信はしていない**。束の画像を人が見て書いた返答を `--vlm-response` で取り込み、数値の出来事に添えられること、出来事が変わって依頼が変わると古い返答を取り込まないことを確かめた。

## 設定（`inspect/0.1`）

パスは設定ファイルのあるフォルダ基準（絶対パスも可）。`clips` か `dance_spec` のどちらか 1 つを書く。未知の鍵は拒否し、`x_` で始まる鍵はどの階層でも許す（スキーマは `src/mv_pipeline/inspection/inspect.schema.json`。`contracts/` の外）。

```json
{
  "schema_version": "inspect/0.1",
  "clips": [
    {"id": "cut07", "path": "clips/cut07.mp4", "frames": [0, 120],
     "origin": {"tool": "…", "model": "…", "job": "jobs/cut07.json", "seed": 42, "start_image": "stills/cut07.png", "prompt_file": "prompts/cut07.txt"}}
  ],
  "reference": [{"path": "sheets/front.png", "view": "front"}, {"path": "sheets/back.png", "view": "back"}],
  "foreground": {"key": {"color": [0, 255, 0], "tolerance": 0.22, "softness": 0.12}},
  "checks": ["continuity", "motion", "shape", "costume"],
  "thresholds": {"jump_min": 0.08},
  "vlm": {"every_s": 1.0, "max_frames": 24, "max_side": 768, "language": "ja"}
}
```

- `clips[]`: `path`（動画か静止画）、`id`（既定はファイル名。英数と `_.-`）、`frames`（見るコマ `[開始, 終了)`。既定は全部）、`origin`（生成の素性。検査には使わず、直す場所と修正計画にそのまま写す。将来の再生成に要る値を書いておく）、`foreground`（このクリップだけの切り抜き）。
- `dance_spec`: dance の spec のパス。`performer.clips` の素材を、spec の区間で実際に出る元のコマの範囲だけ見る（同じ素材を何度使っても 1 回だけ見る）。切り抜きは spec の `performer.key`。素性は `"origins": {"spec に書いた素材のパス": {…}}`。
- `reference[]`: 設定画。`background` は人物の切り抜き方で、`auto`（既定。透明があれば `alpha`、無ければ `border`）・`alpha`・`border`（画像の縁の色を背景とみなす。**推定**で、報告にそう書く）・`none`。`key`（緑背景の設定画）、`box`（正規化の切り出し。三面図の 1 体だけを使うときなど）。複数の設定画（正面・側面・背面など）は、コマごとにそのコマをいちばんよく説明する 1 枚と比べる。欠けは、主な色が欠けない設定画が 1 枚でもあれば出さず（どれでも欠けるときは欠けた色の割合の和がいちばん小さい設定画で書く）、余りは設定画に無い色の割合がいちばん小さい設定画で測る。欠けは色ごとに区間を作り、値はその色が実際に欠けたコマだけで測る（設定画に無い色も、値はしきい値を超えたコマだけで測る。別の色が続けて欠けても色ごとに残す。向き違いの設定画で ΔE `ref_match_de` 以内の色は近い順に同じ色として数えるので、比べる向きが入れ替わっても区間は切れない。1 つの色には 1 枚の設定画から 1 色しか入れず、同じ設定画の別の色どうしは、間の色を挟んでも同じ色にしない）。同じ衣装の向き違いは色の配分がほぼ同じで、色だけでは向きを決められないため（重なりの大きさで選ぶと、コマごとに選ぶ設定画が入れ替わり、背中を向いたコマを正面と比べて欠けを出した）。報告では設定画を `パス（view）` の名前で書く（同じファイルを view なしで何度も使えば `#番号` を足す）。
- `foreground`: 人物の切り抜き。`{"key": {...}}`（緑抜き。dance と同じ式）・`{"box": [x0, y0, x1, y1]}`（固定の箱）・`"none"`。**無いと形状・衣装・設定画との照合・位置の飛び・揺れは見ない**（未実施として残る）。緑抜きは色味の距離で決めるので、キーの色が灰色に近い（くすんだ緑の 3D 描画など）と、既定の `tolerance` 0.22 では肌・髪・白い服まで抜ける。そういう設定には報告の「注意」に下げる値を書く（設定画の `key` も同じ）。
- `checks`: 見る分類（書かなければ 4 つ全部。`[]` なら数値の検査をしない＝VLM だけの検品）。外した分類は未実施として残る。設定画との照合は `costume` に入る。
- `analysis_width`: 解析の幅（既定 320。元より大きくしない）。
- `cues`（全体か `clips[]` ごと）: 演出の時刻（下の「演出の時刻」）。`clips` の書き方だけで使える。

## 演出の時刻（`cues`）

舞台と光で描いた 3D の描画では、カメラのカット・速いカメラの動き・音で光る照明が、画の急変として出来事になる（Blender の 32 秒の本番では、27〜31 件がどれも作った演出だった）。演出の時刻を渡すと、出来事に**重なった演出を書き添える**。

- **出来事は消さない**: 演出と同じ時刻に本当の崩れが出ることもあるので、重なった出来事も要確認のまま残す。「演出との一致」（`events[].cues`）と「異常の可能性」（出来事そのもの）を分けて見られるようにするだけで、判断は人がする。md の冒頭に、重なる出来事と重ならない出来事の数を書く（重ならない出来事から見る）。
- 書き方（時刻はそのクリップの頭が 0 秒。`offset_s` を書くと cue の時刻からその秒を引く）:
  - `cuts`: カットの秒の並び。`moves`: カメラが速く動く区間 `[[始め, 終わり], …]`。`lights`: 照明の演出の区間か秒。
  - `beats`: 拍の格子 `{"period", "k0_time"}`（拍 k は k0_time + period × k 秒）か、拍の秒の並び。
  - `track`: model3d の `render.stage` のトラック（`model3d-stage-track/0.1`。1 つか並び。並びはつないでから読むので、クリップの境目のカットも見る）。コマ T と T+1 の間で、カメラが 0.5 m か 15° かレンズ 2 mm 以上飛んだ所をカット、0.05 m か 1° 以上動いたコマを動きの区間、光の強さ（壁・左右の輪郭光それぞれ・光の柱・塗りの縁）が相対で 50% 以上跳ねた所と、色（壁の明るい帯と暗い帯・輪郭光・光の柱・塗りの縁の `a`・`b`）・模様が切り替わった所を照明の演出にする（毎コマ続けて動く壁の模様のずれと光の柱の向きは、切り替えとしては見ない）。トラックで省いた値は、描く側と同じく、前のコマの値でなく既定の値として比べる（壁の強さ 1・輪郭光 1500・光の柱 0.9・模様 `led`）。塗りの縁の強さと色の既定は .blend で決まるので、片方のコマだけ書いた塗りの縁の強さは比べない。T と T+1 の間の変化は、動画のコマ T（0 から）= T / fps 秒に見える。
    - トラックでは `camera` とその `lens` を省ける。`camera` を省いたコマ（描く側の、腰を追う既定のカメラ。位置はトラックから分からない）を含む組は、カットとカメラの動きを見ない（照明は見る）。その数は報告の `clips[].cues.sources[].frames_without_camera`。レンズは、両方のコマに書いてあるときだけ比べる（両方省けば同じ既定のレンズ）。
  - `light_keys`: model3d の光のキー（`model3d-light-keys/0.1`）の拍の格子。
  - `tolerance_s`（既定 0.05 秒）: カット・区間との時刻の許し。`beat_tolerance`（既定 0.1 拍）: 拍との許し。
- **重ねる信号**: カットは画面全体が変わるので、どの信号でも重なりを書く。カメラの動きは動き・位置・大きさ・輪郭・画の切り替わりの信号、拍は明るさの明滅と配色の急変、照明は明るさ・配色・画の切り替わりの信号にだけ重ねる（拍は細かく、どの時刻にも近くに拍があるので、形の崩れなどには重ねない）。
- `dance_spec` の書き方では使えない（見る素材のコマの時刻が、出力の時刻と違うため）。
- **実素材で**（2026-11-08。Blender の本番の 32 秒、1080×1920・30 fps・960 コマ、`foreground: "none"`）: 5 クリップのトラックと光のキーを渡すと、27 件のうち 26 件が演出の時刻と重なった（カット 11・カメラの動き 9・照明の跳ね 96 か所と拍の格子）。重ならなかったのは、コマ 267 の動きの急変 1 件だけ。照明が音で動く描画では、照明の跳ねが多く（この 32 秒で 96 か所、許しを入れると時間の約 3 割）、明るさの信号は偶然重なることもある。

## 測るものと分類

数値は解析の大きさに縮めたコマから測る。「急変」は前のコマとの差の列で、前後 `window_s`（0.5 秒）の中央値から MAD×1.4826 の `spike_z`（6）倍以上、中央値の `spike_ratio`（3）倍以上、かつ下の最小値以上の所。変わった絵が `pair_max_s`（2 秒）以内に元へ戻れば（入りの前のコマと戻りのコマの差が入りの変化の `return_ratio`（0.5）倍以下）その間 `[入り, 戻り)` が候補（pair）、戻らなければ変わり目の 1 コマ（step。以降は変わったまま）。

| 分類 | 信号 | 測るもの | 最小値（仮） | 要るもの |
|---|---|---|---|---|
| 連続性 | `glitch` 数コマだけの乱れ／`jump` 画の切り替わり | 人物の外（無ければ画面全体）の構造の差（各コマの平均を引いた明るさの差。明るさだけの変化は除く） | `jump_min` 0.06 | — |
| 連続性 | `flicker` 明るさの明滅 | 画面の明るさの平均の差（構造の急変と同じコマは除く） | `flicker_min` 0.04 | — |
| 連続性 | `freeze` 止まったコマ | 前のコマとの差が `dup_max`（0.0005）以下のコマが、動いている所（周りの差が `dup_context`（4）倍以上）で `freeze_frames`（3）コマ以上続く | — | — |
| 連続性 | `duplicate_cadence` 重複コマの周期 | 1 つだけの重複が一定の間隔で 3 回以上（24 コマの絵を 30fps に水増しした素材など）。クリップ全体で 1 つ | — | — |
| 連続性 | `vanish` 人物が消えたコマ | 前後に人物がいて、`vanish_max_s`（0.5 秒）以下だけ人物がいない（端の出入りと長い不在は見ない） | — | 前景 |
| 動作 | `motion_spike` 動きの急変 | オプティカルフロー（Farneback、解析の半分の大きさ）の大きさの p95（体の高さ／コマ。前景が無ければ画面の高さ）。人物が前後のどちらかにしかいないコマは測らない（出入りは消失で見る）。逆向きに戻れば pair | `motion_min` 0.05 | — |
| 動作 | `teleport` 位置の飛び | 人物の重心の移動（体の高さ／コマ） | `teleport_min` 0.06 | 前景 |

| 形状 | `area_pop` 大きさの急変 | 人物の面積の比 \|ln\| | `area_min` 0.18 | 前景 |
| 形状 | `fragment` 部分の分離・増減 | 人物の塊（画面の 0.15% 以上で、いちばん大きい塊の 1% 以上）の数が、いつもの数と `fragment_max_s`（0.5 秒）以下だけ違う | — | 前景 |
| 衣装 | `costume_pop` 配色の急変 | 人物の内側の画素の配色（彩度の低い画素は明るさ 8 段、ほかは色相 16 × 彩度 3 × 明るさ 3）の、前のコマとの Bhattacharyya 距離 | `palette_min` 0.15 | 前景 |
| 衣装 | `costume_drift` 冒頭からの配色のずれ | 冒頭 `anchor_s`（0.5 秒）の配色からの距離が `drift_min`（0.35）以上の続き（`min_segment_s` 0.25 秒以上）。いちばん違う帯（頭・上半身・下半身）も書く | — | 前景 |
| 衣装 | `reference_missing` 設定画の色の欠け | 設定画の主な色（割合 `ref_min_weight` 5% 以上）が、コマの人物で設定画の割合の `ref_missing_ratio`（0.25）倍より少ない続き。色の差 ΔE `ref_match_de`（18。明るさの差は半分に数える）以内を同じ色と数える | — | 前景・設定画 |
| 衣装 | `reference_extra` 設定画に無い色 | どの設定画の色からも ΔE `ref_extra_de`（30）より遠い画素が `ref_extra_min`（12%）以上の続き。その色も書く | — | 前景・設定画 |

**まとめ方と分類の規則**（決め方の約束で、推定ではない）:

- 同じ分類で区間が半分以上重なる（または短い方がほぼ長い方の中にある）信号と、どちらも 3 コマ以下で 1 コマ以内に接する信号を、1 つの出来事にまとめる。水増しの周期はほかとまとめない（中の乱れを飲み込まない）。
- 主な分類は、含まれる信号の分類のうち **連続性 → 形状 → 衣装 → 動作** の順で先のもの。連続性は人物の外（背景）まで変わった・明滅・止まった所なので、そのとき人物の輪郭や配色の変化は結果として扱う。ほかの分類は `categories` に残す。
- 出来事の区間は全部の信号から取る。ただし、組になった信号の戻りのコマにある変わり目だけの信号（戻りの動きを別の測り方で拾ったもの）は除く。近くの別の変わり目は区間に入れる（直す場所から漏らさない）。

## 直す場所と手当ての候補

出来事の `target`:

| 書き方 | `target` |
|---|---|
| `clips` | `kind: "clip"`・`path`（設定に書いたパス）・`sha256`・`source_frames`（元のコマ `[開始, 終了)`）・`source_t`（秒）・`origin` |
| `dance_spec` | `kind: "dance_clip"`・上と同じ欄・`spec`・`uses`（`[{pointer: "/performer/clips/2", clip_index, shot_frames: [[開始, 終了)…], shot_t}]`。その元のコマが spec のどの clip で、出力のどのコマ・秒に出るか。blend の窓で前の clip が続く所も数える） |

dance で、spec の区間で一度も出ない元のコマ（`speed` で飛ばすコマなど）で見つけたものは `unused` に分け、数だけ報告する。

`actions` は規則で出す提案で、何も実行しない:

| `kind` | 出す条件 | 中身 |
|---|---|---|
| `regenerate_segment` | 重複の周期以外 | 前後のコマ（`anchors`）を始点・終点にして、その区間だけを生成し直す |
| `replace_frames` | 2 コマ以下の連続性・形状・動作で、絵が元に戻るもの（組 pair か区間 segment の信号がある）か、VLM だけの指摘 | 前後のコマで置き換える（保持か混合。前後の絵が大きく違うと、保つと止まり、混ぜると二重写しになる）。dance の人物の素材なら `in_orpheus: true` で、spec の `performer.replace_frames` に足す 1 行を `spec_entry`（`pointer` と `value`）に付ける（dance-shot/0.3。保持だけ。`docs/dance.md` の「元のコマの対応」）。fx の素材は `in_orpheus: false` |
| `interpolate` | 止まったコマ。2 コマ以下の形状・動作で、絵が戻らない変化（step だけ。速い動きの途中のコマ） | 補間（外部の道具）で作り直すか、生成し直す。実素材では ffmpeg の minterpolate が速い腕の動きを追えず二重写しが残ったので、確実なのは生成し直し（学習型の補間は未確認） |
| `decimate` | 重複の周期 | `ffmpeg` の `decimate=cycle=N` などで除いてから使う（`speed` を変えるときは先に） |
| `regenerate_with_reference`・`color_match` | 衣装（主な分類か、設定画の信号・VLM の衣装の指摘がある） | 設定画を参照に入れて（強めて）生成し直す。尺を短く切る。配色の差だけなら仕上げ（dance の hooks の `performer` など）で合わせる |
| `trim` | 見た範囲の端に近い（範囲の 20% か 0.5 秒以内） | 使う区間を縮める（dance は `clips[].source_start`・`start`・`end` を直す） |

## 修正計画（`fix_plan.json`）— 自動再生成の入口

`inspect-fix-plan/0.1`。`status: "proposed"`、`executor: null`（自動の再生成は未実装）。クリップごとに、すき間が `plan_merge_s`（0.15 秒）以下の出来事を 1 つの区間にまとめ（間の短い良いコマを、前後の生成し直しに挟まないため）、前後に `plan_pad_frames`（2）コマ広げる。重複コマの周期の出来事はほかとまとめない（手当ては間引きで、生成し直す区間をクリップ全体に広げないため）。区間ごとに:

- `source_frames`・`source_t`（生成し直す元のコマ）、`event_frames`、`events`（出来事の ID）、`categories`、`evidence`
- `anchors`: 前後のコマ `{frame, image}`。画像は**元の大きさの PNG**（`anchors/<クリップ>_f<コマ>.png`）で、始点と終点を指定できる生成器にそのまま渡せる
- `origin`（素性）、`actions`（区間の `regenerate_segment` を先頭に、出来事の手当ての候補を並べる。種類とコマが同じものだけを 1 つにし、コマの違う置き換えや補間は全部残す）、dance なら `spec` と `uses`（生成し直す区間のコマが出る clip と出力のコマ・秒を全部。前後に広げた分も含む）

将来の自動再生成は、この区間・前後の画・素性から生成器のジョブを作り、差し替えた素材で同じ検品をもう一度通す形を想定している（起動は毎回ユーザーの承認。GPU や有料 API の費用がかかるため）。

## VLM（ニューラル品質評価）

数値の検査は形や配色の統計しか見ない。指が 6 本・顔が別人・物理的にありえない姿勢のような意味の分かる不自然さは、画像を読めるモデル（VLM）に見せる。Orpheus は**依頼の束を書いて、ユーザーが明示した外部プログラムを呼ぶだけ**。

```sh
uv run mv inspect check inspect.json --vlm-packet                     # 依頼の束だけを書く（何も送らない）
uv run mv inspect check inspect.json --vlm vlm.json                   # 手元で動く VLM（sends_data: false）
uv run mv inspect check inspect.json --vlm vlm_claude.json --allow-send   # 素材を外へ送る VLM（sends_data: true）
uv run mv inspect check inspect.json --vlm-response response.json     # 手で書いた／別の所で作った返答を取り込む
uv run mv inspect check inspect.json --vlm-response old.json --vlm-legacy-response   # request_sha256 の無い古い形の返答（互換の扱い）
```

- `--vlm-packet` は束を書くだけの指定で、`--vlm` とは同時に使えない（送らないつもりの指定で送信が起きないように）。`--vlm` と `--vlm-response` も同時に使えない。
- **見せるコマ**: 出来事の山のコマを先に、残りは `vlm.every_s`（1 秒）ごとの見本。合わせて `vlm.max_frames`（24）まで。
  - 山のコマが枠より多ければ、クリップに順に 1 つずつ配り、クリップの中では時間に散らして選ぶ（端と真ん中を含む等間隔の位置）。見本も同じく、クリップに配って時間に散らす（前は先頭から枠まで取り、後ろの出来事や後のクリップを見せなかった）。
  - 見せなかった出来事（ID・区間）と、クリップごとの見せたコマの数と時刻の幅を、報告の `vlm.frames`（`unsent`・`clips`）と md に書く。**VLM が見ていないことは、異常が無いことではない**（数値の出来事としては残る）。
  - 長い辺 `vlm.max_side`（768）の JPEG。設定画も同じ大きさの PNG で入れる（`reference[].box` があれば、数値の照合と同じく切り出してから）。
- **依頼の束**（`vlm/request.json`、`inspect-vlm-request/0.1`）: `instructions`（`vlm.language` が `ja` か `en`）、`categories`（分類の定義。数値の検査の `checks` によらず 4 つと `other`）、`reference`、`frames`（`id` = `クリップ@コマ`・クリップ・コマ・秒・`why`・`file`）、`response_schema`。画像ごとの `sha256` も入れるので、素材を同じ名前で差し替えると依頼の sha256 も変わり、古い返答は取り込まない。
- **返答**（`inspect-vlm-response/0.1`）: `tool`（`name`・`version`・`model`）、`request_sha256`（今回の依頼の束 `vlm/request.json` の sha256。**必須**で、違えば止める。同じコマの id（`クリップ@コマ`）の、別の依頼・別の素材への返答を取り込まないため。無い古い形の返答は、`--vlm-legacy-response` を付けたときだけ互換の扱いで取り込み、報告の VLM の欄に `legacy_response: true` と注意を残す）、`findings`（`frame_id`・`category`（4 つか `other`）・`description`・`box`（正規化。任意））。依頼に無いコマの id は止める。拒否・打ち切り・失敗で見られなかったコマは `x_unreviewed`（`[{frame_id, reason}]`）に書くと、警告として報告に残る（指摘が無いこととは違う）。
- **取り込み**: 同じクリップの近いコマ（区間か前後 1 コマ）に、添えてよい数値の出来事（3 コマ以下か分類が同じもの。重複コマの周期は除く）があればそれに添え（`evidence: measured+estimated`。主な分類は数値の規則のまま、VLM の分類は `categories` に足す。隣のコマの指摘なら出来事の区間をそのコマまで広げ、秒・直す場所・手当ての候補を作り直す）、無ければ VLM だけの出来事（`estimated`）を作る。どちらも直す場所と修正計画に入り、VLM が衣装と言った出来事には衣装の手当ての候補も付く。合否には使わない。
- **設定**（`--vlm` の JSON。`docs/adapters.md` と同じ約束）: `tool`・`version`・`argv`（`argv[0]` は存在する絶対パス。シェルは使わない。`{request}`・`{output}`・`{packet}` を置き換える）・**`sends_data`（必須）**・`timeout_s`（既定 900）。**argv はローカルで実行するプログラム**なので、中身を確かめた設定だけを使う。`sends_data: true` の設定は `--allow-send` が無いと、重い処理の前に止まる。
- **代役**（`scripts/vlm_standin.py`）: 画像を読まず、ネットワークにも出ない。`--flag 'id:分類:説明'`・`--echo-events 分類`・`--unreviewed id` で返答の形を確かめる（テストと CI 用）。
- **Claude のアダプタの例**（`scripts/vlm_claude.py`）: 設定画とコマを Messages API の画像入力で送り、構造化出力（`output_config.format`）で返答の形を縛る。既定のモデルはスクリプトの `DEFAULT_MODEL`（`--model` で変える）・effort `high`・6 枚ずつ。設定画はどのバッチでも同じ前置きにしてキャッシュに載せる。拒否されたときの別モデルでの再実行（`fallbacks: "default"`）を有効にしている。拒否・打ち切り・失敗のバッチのコマは `x_unreviewed` に残す。anthropic の SDK を入れた**別の Python**で動かし、鍵は SDK の既定の探し方（`ANTHROPIC_API_KEY` など）で読む。**送信と課金が起きる**ので、設定には `"sends_data": true` を書く。`--dry-run` で送らずにバッチの数を見られる。2026-11-07 にユーザーの了承のうえで実際の API に 3 回送り、どの回も最後まで通った（上の「実素材での確かめ」）。バッチごとのトークン数を `x_batches[].usage`、合計を `x_usage` に書く（報告の VLM の欄にも出す。料金は書かないので、モデルの料金表で計算する）。返答の形（構造化出力のスキーマ）はどのバッチも同じ（列挙は依頼の全コマ。バッチの外のコマの指摘は捨てる）にして、設定画の前置きをキャッシュから読ませる。

```json
{"tool": "claude", "version": "anthropic SDK の版", "sends_data": true, "timeout_s": 1800,
 "argv": ["/abs/venv/bin/python", "/abs/Orpheus/scripts/vlm_claude.py", "--request", "{request}", "--output", "{output}"]}
```

## 出力

既定は設定の隣の `inspect_report/`（`--out` で変える）。出力先には印の `inspect_output.txt` を置き、印のある出力先だけ、前の実行の `stills/`・`anchors/`・`metrics/`・`references/`・`vlm/` と報告を入れ替える。印が無いのにそれらがある出力先には書かない（ほかの作業を消さない）。

**実行ごとの書き方**（途中で失敗・強制終了しても、前の成功した結果を壊さない）:
- 1 回の実行は、出力先の中の作業用フォルダー `.staging-<run_id>/` に全部を書く。最後まで済んだときだけ、前の結果と入れ替える。
  - 入れ替えでは、前の結果をいったん `.previous-<run_id>/` へ動かし、新しい結果を入れてから消す。報告の JSON は先に外して最後に置くので、報告が見える間は、その報告の静止画などがそろっている。
  - 入れ替えの途中で失敗したとき（ファイルがほかのアプリに開かれていて動かせない・Ctrl+C など）は、その場で前の結果へ戻し、途中まで入れた新しい結果を消してから、元のエラーで止まる。
  - 強制終了などで戻せなかったときのために、前からあったものの一覧を `.publish.json` に書いておく。次の実行の初めに、前の結果へ戻す（報告の「注意」に書く）。その場で戻す処理も失敗したときは、`.publish.json` と `.previous-<run_id>/` を残して同じく次の実行で戻し、そのことを実行の記録のエラーの文に書く。
- 同じ出力先では 1 つの実行だけが動く（出力先の `.lock` を OS のロックで持つ。fx・dance と同じロックで、強制終了でも外れる）。ほかの実行が使っている間に始めた実行は、何も触らずに止まる（動いている実行の作業用フォルダーを、止まった実行の跡と取り違えて消さないため）。
- 測る途中・VLM の途中で失敗したときは、作業用フォルダーを消し、前の結果をそのまま残す。VLM のプログラムのログと返答だけは `failed/<run_id>/` に残し（新しい 5 回分）、エラーの文もそこを指す。
- `inspect_runs.json`（`inspect-runs/0.1`）に、実行ごとの `run_id`・状態（`running` / `succeeded` / `failed`）・開始と終了の時刻・設定の sha256・エラーの文・入力の sha256 を残す（新しい 50 回分）。強制終了した実行は `running` のまま残るので、次の実行がそれを `failed`（`interrupted: true`）にして、残った作業用フォルダーを消す。
- 報告の `run`（`id`・`started_at`・`finished_at`・`inputs`）に、この実行の入力（設定・動画・設定画・dance の spec・演出の時刻のファイル（`cues.track`・`cues.light_keys`。役は `cues_track`・`cues_light_keys`）・VLM の設定・依頼・返答）の sha256 を書く。

## 限界

- **実素材では 2026-11-07 に試しただけ**（上の「実素材での確かめ」。わざと入れた異常 7 つは全部見つかったが、見落としの率は測っていない）。合成素材は平らな塗りの図形で、生成動画の質感・ぶれ・圧縮の乱れ・照明の変化とは違う。しきい値は実作品で直す前提。
- 急変は周りのコマとの比べ（中央値と MAD）で見るので、速い動きの続く所では基準が上がり、そこに出た崩れを見落とすことがある（実素材で、補間で作った二重写しのコマ 81 を見落とした。輪郭の変化 0.31・0.36 は最小値を超えたが、急変の基準に届かなかった）。半透明・二重写しそのものを測る検査はまだ無い。
- 動画の読み方: ffmpeg で、タグが `bt709` の動画は BT.709、ほかは BT.601 として読む（タグの無い BT.709 の動画は色がずれる。`docs/dance.md` の限界と同じ）。コマ番号は復号の順で、可変フレームレートでもコマを足し引きしない。秒はコマ番号 ÷ 表示の fps。
- 形状・衣装・設定画との照合・位置の飛び・揺れは**人物の切り抜きが要る**。緑背景か固定の箱だけで、背景のある場面の人物は切り抜けない（場面のカットは連続性と動きの急変だけを見る。意味の分かる検査は VLM）。
- 頭・上半身・下半身の帯は、立った全身の人物の囲みの高さの割合（0.2・0.55）で、体の部位の検出ではない。
- 設定画との照合は配色だけ。向き・陰影・照明・動きのぶれで色の割合は変わる（正面の設定画だけだと、振り向いたコマで欠けが出やすい。背面の設定画も渡す）。色だけでは向きを決められないので、向きの違う設定画で色の違う所（正面だけの飾りなど）は、ほかの向きで説明できれば欠けにしない。形・顔・小物の照合はしない。
- 暗い背景の設定画（キャラシートなど）を `border` で切り抜くと、黒髪・黒い服・靴が背景と同じ色として抜け、背景の模様が混ざる（実素材で確かめた。`references/` の画像で見える）。そのときの照合は残った色（肌・服の明るい色）だけでしている。透明で抜いた設定画（`alpha`）か緑背景の設定画（`key`）を渡す。
- オプティカルフローは平らな塗りの所で不安定。動きの急変は補助の信号で、ほかの信号と同じ所に出ることが多い。
- VLM の指摘は推定で、見せたコマ（既定で最大 24 枚）しか見ていない。同じ依頼でも実行ごとに指摘の数と分類が変わる（実際の API で 3 回: 5 コマは毎回、2 コマは 1 回だけ）。
- 自動の再生成・コマの差し替え・補間はしない（提案だけ）。
