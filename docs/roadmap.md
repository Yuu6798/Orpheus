# Orpheus ロードマップ

2026-10-24 版（2026-10-25 に段階 1 の結果を反映）。実装前の計画であり、実装済みの機能とは区別する（実装済みは README と各 docs を参照）。工数・日程は推定。

## 目標

**作品で使える映像表現を蓄積し、CLI と設定変更で繰り返し使える制作ツールにする。**

- 同じ素材から作れる画の幅を広げる（空間の前後関係、対象物への光の当たり方、カメラとピント）。
- 通常の制作はソースを読まず、毎回スクリプトを書かずに、CLI と設定ファイルで回す。
- 成果は「同じ素材・同じ区間で、現行版と改善版を並べた比較映像」で示し、採用はユーザーが決める。

## 原則

- 動く既存ツールを優先する。全面的な書き直しを前提にしない。
- `contracts/` の 3 契約は無断で変えない。新しい設定は版付きの別スキーマとして置き、昇格は承認制。
- 推定を実測扱いしない。技術的な合格（technical_pass）と作品への採用（accepted）を分けて記録する。
- 生成→実測→検証→修正→再生成の順を守る。生成物の開発中に測定器・検証器へ機能を足さない。採点器を作らない。
- 依頼のない送信・公開をしない。素材・鍵・モデル・動画・未公開の作品情報をリポジトリに入れない。

## 段階

### 段階 0　安全網と表現の実証基盤（このリポジトリで完結）

- 依存の既知脆弱性の解消（Pillow 13.0.0 / pytest 9.0.3、fast-uri）、uv 0.13.5 以上の強制、最小 CI（Python・Node・依存監査・Remotion 実描画は任意）、Dependabot、CLAUDE.md。
- 演出エンジン fx v0.1: 空間レイヤー（背景・人物・前景のマスク、重なり順、移動量、霧・火の粉）と局所照明（光の位置・色・強さの時間変化、受光マスク、輪郭光、照り返し、光点）、カメラのキーフレーム、深度視差。
- `mv fx render` で **base / layers / light / both の 4 版と 2×2 比較映像**を同じ区間・同じ音声・同じ解像度で出す。`mv fx stills` で静止画シート、`mv fx accept` で採用記録。
- `mv fx legacy` で手元の実制作レンダラを**リポジトリに入れずに**同じ台帳の下で呼ぶ（レンダラと設定の sha256、ログ、出力検査を run に残す）。
- 合成素材のデモ（`mv fx demo`）で CI が描画まで通す。

**完了条件:** 共通の入口から 4 版の比較映像が出せ、光が対象物ごとに違う当たり方をしている（受光マスクの外は変わらない）ことをテストと目視で確認できる。

### 段階 1　実作品の素材で比較を作り、指摘を一度反映する（素材のある環境で）

1. 公開済みの作品から、静止画（2.5D）のカットが続く区間を 1 つ選ぶ。fx v0.1 は 1 つの spec で静止画 1 枚を描くので、区間はカットの尺に合わせる。マスク（手描き・既存の切り抜き・深度のしきい値）と spec を用意する。
2. 公開版の同じ区間を切り出して基準（現行版）として並べる。エンジンをまたぐ画素比較はしない（目視の並置）。
3. `mv fx stills` で光源の位置を確かめてから `mv fx render` で 4 版を出し、ユーザーが比較して指摘する。
4. 指摘を一度反映し、採用した設定と出力を `mv fx accept` で残す。

当初は制作中の作品の基準画で行う計画だったが、制作中の作品の進行に触れず、公開版をそのまま基準にできるため、公開済みの作品に切り替えた（2026-10-25）。公開版がある場合、`mv fx legacy` で実制作レンダラを動かし直す必要はない。

**完了条件:** ユーザーが改善点と修正点を判断でき、採用した設定が spec と run として残っている。

#### 段階 1 の結果（2026-10-25）

- 対象: 公開済みの第 1 作の夜のカット（光る刀・稲光・灯籠）。カット内の約 5.4 秒（129 フレーム、前後とも硬いカット）。基準は実際に公開したマスター（歌詞テロップ入り）。素材のある PC のセッションで実施した（以下、PC 側の報告とユーザーの判定による）。
- spec: カメラは公開版の設定（ズーム・視差の振り）に合わせた。レイヤーは人物の plane・人物の後ろの薄い霧・手前の花びら。光は絵の中の光源の位置に 4 灯（刀身＝人物に載せて輪郭光、稲光＝音の強打の時刻に明滅、左右の灯籠＝石段に照り返し）。
- 調整: 最初の静止画シートで照り返しが不透明な柱に見え、霧で全体が白っぽくなったため、照り返し 0.7→0.3、霧 0.18→0.08 に下げてから本番を描いた。4 版とグリッドはすべて technical_pass。
- ユーザーの判定: 「世界観がダークなので base でも成立するが、both がかなり良い」→ **both を採用**。撤退条件には当たらない。
- 段階 1 で見えた課題（段階 2 以降の候補。生成側の追加で、計器ではない）:
  - 色調整・周辺減光・粒状感が無い。公開版の見た目に揃えるには必須（実制作レンダラの区間ごとの調色に相当）。
  - 深度視差の軸（どの深度を動かない基準にするか）を指定できない（公開版は 0.35 相当、fx は 0.5 固定）。
  - 光の明滅を音の強打に合わせる作業が手作業（解析した強打から強さのキーを作れると減る）。
  - 歌詞テロップ（透過連番）の合成が無い。実際の MV に使うには要る。
  - 既存の切り抜きマスクの欠け（刃先・足元）を手で補った。道具化するかは回数を見て決める。
  - 照り返しと霧の初期値が実素材には強すぎた（デモ基準の値）。実素材向けの目安を docs に書く。

### 段階 2　カメラ演出と演出部品の再利用

- カメラ軌道の複数キー・加減速・停止、奥行きに応じたピント送り（深度ぼけ）。照明だけの版と比べて効果を確認する。
- 採用した表現を「演出部品（プリセット）」にまとめ、触るパラメーター（素材・マスク・強度・時間）を絞る。
- 別のカットに設定変更だけで適用し、作品固有コードなしで再利用できるか確かめる。まず段階 1 で採用した設定を、同じ作品の別カットに当てる。
- 段階 1 の課題のうち、公開版の見た目に揃えるための色調整・周辺減光・粒状感を優先候補にする。

**完了条件:** 元のカットと別のカットで、同じ演出部品を設定変更だけで使え、採用版を再出力できる。

### 段階 3　作品で必要になった表現と操作を足す

- 髪・袖の小動作（支点・振幅・周期）、文字と場面の一体化（人物の後ろに隠す、追従、奥行き）、場面転換。効果が見込める順に 1 種類ずつ。
- 区間描画を使う短いプレビュー、比較版の整理、修正メモ。GUI・波形編集・影響範囲を自動判定するキャッシュは、制作上の負担が確認できた箇所から。

### 並行: 工程の骨格の実害修正（契約不変）

- 描画が失敗すると前回成功の記録が消える問題、preview/final のキャッシュ外れ、歌詞時刻 1 行の修正で手書きのハッシュ更新が要る問題、`update-lyrics` の行き止まり、歌詞取り込みの全体拒否、型付き例外と終了コード、描画中の逐次ログと timeout。
- それぞれ再現テストを付けた小さな PR で。歌詞時刻だけの修正で演出の再確認を省くかはユーザー判断。

## 判断ゲート（段階 1〜2 の後）

材料: 段階 1〜2 の比較結果と採用記録、legacy 経由の描画記録。ユーザーが選ぶ。

| 選択肢 | 中身 |
|---|---|
| 統合 | 実制作レンダラの共通部分を fx エンジンへ寄せて 1 本にする（取り込み方法は public/private の判断とセット）。作品固有の効果は作品ごとの設定に分離。Remotion は引退 |
| 併存 | fx エンジンと実制作レンダラを legacy 接続で併用し続ける |
| Remotion 進化 | Remotion を主経路に戻し、契約を段階的に拡張する（実制作での使用実績が無いため、スパイクで成立を確かめてから） |

撤退条件（推定の目安）: 段階 1 の比較がユーザーに採用されない、または段階 2 で別カットへの再利用が設定変更だけで成立しない場合は、段階 3 に進まず原因を記録して計画を見直す。

## 効果の確認（記録の取り方。計器は作らない）

- 映像: 同じ素材・区間・音声・解像度・fps・seed で比べる。光が全体の明るさ変更でなく対象物への当たり方に見えるか、マスクの境界・欠け・ちらつき・字幕の読みやすさ、意図しない変化が無いか。
- 作業: 同じ修正作業を従来方式と比べ、ソース閲覧・コード生成の有無、入出力トークン数、修正版が出るまでの時間、再試行回数、別カットへの適用可否を記録する。**削減率は未測定**で、トークン数が取れない場合は断定しない。

## やらないこと（当面）

- 全制作スクリプトの一括移植、大規模 GUI、独自ノードエディター、分散描画、独自の動画生成モデル。
- 単一画像から隠れた面・材質・大きな姿勢変化を推定すること（追加素材・3D・動画生成と組み合わせる）。
- 採点器・自動合否の開発。
