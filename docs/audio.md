# 音の道具（`mv audio`）

曲の音から作る記録（拍の格子・打点）を、音源か analysis.json の隣の別ファイルに書く（実験的）。打点からは fx-shot の光の
強さのキーも作る。記録の形は `contracts/` の外で、analysis.json の契約は変えない。値はすべて推定（聞いて確かめるまで実測扱いに
しない）。grid と hits には librosa が要る（`uv sync --locked --extra analysis`）。

```sh
uv run mv audio grid song.wav --bpm-min 88 --bpm-max 91                      # 探す。song.grid.json を音源の隣に
uv run mv audio grid song.wav --bpm-min 172.5 --bpm-max 175.5 --fair-refine --downbeat chroma
uv run mv audio grid projects/demo --bpm 174 --phase 0.02 --downbeat chroma   # 決めた格子を記録して確かめる（analysis.grid.json）
uv run mv audio hits song.wav --grid song.grid.json                           # 強打と打点。song.hits.json を音源の隣に
uv run mv audio keys song.hits.json --spec spec.json --light lightning --base 0.12   # spec_keys.json を spec の隣に
```

## 拍の格子（`mv audio grid`）

曲の音の立ち上がりに、一定のテンポの格子を当てはめて、拍と小節の頭の時刻を推定する。テンポが途中で変わる曲には向かない
（記録のずれの確かめで分かる）。

### 探し方（`--bpm-min`・`--bpm-max`）

1. 音を元のサンプリング周波数のまま読み、左右を平均してモノにする。librosa の `onset_strength`（hop 256）を最大値で割る（o）。
2. **点数**: 格子 `phase, phase + period, …` の各点（o のフレームへ `searchsorted`）の前後 `w = int(tol / (hop / sr))` フレームの
   o の最大を、格子の順に float32 で足し、点の数で割る。
3. **粗い探索**: bpm を `--bpm-min` から `--bpm-max` の手前まで 0.02 刻み、位相を 0 から 1 拍の手前まで 0.01 秒刻みで総当たりする
   （tol 0.03 秒）。点がいちばん高い組を採る（同じ点なら先に見つけた組）。
4. **細かい探索**: bpm ±0.05 を 0.002 刻み、位相 ±0.02 秒を 0.002 秒刻みで、tol 0.02 秒の点が今の最良の点を超えたら置き換える。
   - 今の最良の点は粗い探索の点（tol 0.03 秒）のまま比べるので、窓が狭いぶん点が下がり、**ふつうは置き換わらない**
     （実制作の台本と同じ。記録の `fit.refined` で分かる）。
   - `--fair-refine` は、細かい探索の前に、粗い探索の最良を tol 0.02 秒で採点し直し、同じ窓どうしで比べる。
5. **ずれの確かめ**: o の山（`peak_pick`）のうち、格子の各点にいちばん近い山が ±60 ms 未満なら合致とし、ずれ（山 − 点）の平均と
   標準偏差、曲を 3 つに分けた区間ごとのずれの平均を残す。区間ごとの平均が流れていれば、テンポが少し違うか、途中で揺れている。
   立ち上がりの検出は遅れる側に偏るので、平均が数 ms〜十数 ms 正でも格子がずれているとは限らない。

探す範囲が広いほど時間がかかる（総当たり）。3 BPM の幅・4 分の曲で数秒。

### 決めた格子（`--bpm`・`--phase`）

探さずに、その格子（拍 0 の時刻 `--phase` 秒、`--bpm`）で拍と小節の頭を出し、ずれを確かめて記録する。耳で決めた格子や、
ほかの道具で決めた格子を、同じ形で残すときに使う。`--bpm-min`・`--bpm-max`・`--fair-refine` とは一緒に使わない。

### 小節の頭（`--downbeat`）

`downbeat_phase` は、拍の番号 % `--beats-per-bar`（既定 4）がこの値の拍を小節の頭にするという意味。

- `onset`（既定）: 格子の各点の o（点の直後のフレーム）を、拍の番号 % `beats_per_bar` ごとに平均し、いちばん高い位相を採る。
  - 点の直後の 1 フレームだけを見るので、立ち上がりが鋭い音では、拍とフレームの端数で値が変わる。候補どうしの差が小さければ
    当てにならない（記録の `downbeat.scores` で確かめる）。
- `chroma`: 和声の変化で選ぶ。
  - 22050 Hz のモノで読み、調波成分（margin 3）の `chroma_cqt`（hop 256）を取る。
  - 8 分の格子（`phase + k × period/2`。0 秒以上で最初の点から）の各点で、点の 20 ms 後〜8 分後と、8 分前〜20 ms 前の
    平均の chroma（長さ 1 に正規化）の `1 − 内積` を出す。
  - 格子の番号 % `2 × beats_per_bar` ごとに平均し（`downbeat.eighth_slots`）、拍に乗る番号のうち、いちばん高いものを採る。
  - 曲を 3 つに分けた区間ごとに選んだ位相も残す（`downbeat.parts`。そろっていれば安定）。
  - 和音が小節の頭で変わる曲に向く。時間は 4 分の曲で 20 秒ほど。

### 記録（`audio-grid/0.1`）

出力の既定は、音源なら `<音源の名前>.grid.json`（音源の隣）、analysis.json のあるフォルダを渡せば `analysis.grid.json`（analysis.json
の隣。音源の sha256 が analysis.json と違えば止める）。同じ中身なら書き直さず `unchanged`、中身が違えば `--force` が要る。
日時は書かないので、同じ入力からは同じバイト列になる。
`--out` が入力（音源と、フォルダを渡したときの analysis.json）と同じファイルなら、`--force` でも書かない。記録は、同じフォルダに
新しく作った一時ファイル（ランダムな名前）に書いてから置き換える（既にある同じ名前のファイルや、リンクの先は書き換えない）。

| 欄 | 中身 |
|---|---|
| `estimated` | いつも `true`（推定） |
| `audio` | パス（フォルダを渡したときは analysis.json の書き方のまま）・sha256・サンプリング周波数・チャンネル数・長さ |
| `bpm`・`period_s`・`phase_s` | 格子（拍 k の時刻 = `phase_s + k × period_s`） |
| `beats_per_bar`・`downbeat_phase` | 小節の拍の数と、小節の頭の位相 |
| `beats_s`・`downbeats` | 拍の時刻と小節の頭の時刻（曲の終わりまで） |
| `fit` | `mode`（`search`／`fixed`）、点数。探したときは粗い探索の結果（`coarse`）、`refined`、`fair_refine` |
| `downbeat` | 選び方（`method`）、位相ごとの点（`scores`）。`chroma` なら 8 分の番号ごとの値・最初の 8 分の時刻・区間ごとの選び方 |
| `drift` | 合致した拍の数・ずれの平均と標準偏差（ms）・3 つの区間ごとの平均 |
| `settings`・`tools` | 探し方の値と、librosa・numpy・soundfile の版 |

`beats_s` と `downbeats` を持つので、dance と fx-timeline の `beats` に `{"path": "song.grid.json"}` でそのまま渡せる
（拍と小節の参照・snap に使える）。model3d の `plan.light_keys` の `grid` には、`{"period": period_s, "k0_time": phase_s}` から作れる
（拍 0 の時刻は、描く窓の頭からの秒に直す）。

## 打点（`mv audio hits`）

曲の音から、2 種類の打点の時刻と強さを推定する。どちらも実制作の台本と同じ手順で、音は `librosa.load` で 22050 Hz のモノに
してから調べる。

- **強打（`strong`）**: ときどき光らせるもの（稲妻の明滅など）に使う、疎な一覧。
  - `onset_strength`（hop 512）の山を `peak_pick` で選ぶ。前後の最大 10・前後の平均 50 フレーム、間隔 20 フレーム（約 0.46 秒）、
    delta は `onset_strength` の 97 パーセンタイルの半分。
  - 強さ 0 の山は除く。無音やほぼ無音の音源では 97 パーセンタイルが 0 になって delta も 0 になり、値 0 の平らな所が間隔ごとに
    山に選ばれるため（そのままだと `mv audio keys` が無音の間に光る）。音のある曲では、選ばれる山はいつも 0 より大きい。
  - 時刻は、山のフレームの時刻に `--strong-shift-ms`（既定 −16.7）を足したもの。0 秒より前になったものは捨てる。
  - 強さは、山の `onset_strength` を `onset_strength` の 99 パーセンタイルで割った値。
- **帯域差分の打点（`onsets`）**: カットを合わせるときなどに使う、強さつきの密な一覧。
  - n_fft 1024・hop 64（約 2.9 ms）の |STFT|² を 30〜11000 Hz で足し、`log1p(1000 × 和)` の前のフレームとの差（負は 0）を取る。
  - その山を `peak_pick` で選ぶ（前後の最大 20・前後の平均 40、delta 0.05、間隔 20 フレーム）。
  - 時刻は、山のフレームの時刻に `--onset-shift-ms`（既定 +18.7）を足したもの。強さは、山の差を山の差の 99 パーセンタイルで
    割った値（1 を超えることがある）。
  - 音の始まり（0 秒の近く）にも、無音から音への立ち上がりとして打点が出ることがある。
- **時刻の補正**: 既定値は、実制作が合成のクリック（雑音の立ち上がりと 60 Hz の低い打音）で測った検出の偏り（強打は 16.7 ms
  遅れ、帯域差分は 18.7 ms 早い）を打ち消す値。この手順のまま使うときだけ当てはまる。0 にすれば、検出したフレームの時刻のまま。
  - 同じクリックで確かめると、補正した帯域差分の打点は 29 個のクリックすべてにあり、ずれは平均 +0.3 ms・最大 1.8 ms。
    強打は 15 個で平均 +4.9 ms（補正しなければ +21.6 ms）。強打は hop 512（約 23 ms）の刻みなので、帯域差分より粗い。

### 小節と拍の位置（`--grid`）

同じ音源の `mv audio grid` の記録を渡すと、強打と打点に小節（`bar`）と拍（`beat`）の位置を付ける（実制作の縦の Shorts の台本と
同じ式）。`b = (t − 最初の小節の頭) ÷ period`、`bar = floor(b ÷ 拍数) + 1`、`beat = b − 拍数 × (bar − 1) + 1`。
最初の小節の頭は格子の記録の `downbeats` の最初の値で、それより前は 0 小節目。

- 小節の頭のわずかに前の打点は、前の小節の 5.0 拍目近く（4.995 以上）になる（実制作の記録にも 1 つある）。
- 格子の記録の音源（sha256）が違えば止める。

### 記録（`audio-hits/0.1`）

出力と書き直しの決まりは `mv audio grid` と同じ（`<音源の名前>.hits.json`、フォルダなら `analysis.hits.json`）。`--out` は入力
（音源・analysis.json・`--grid` の記録）と同じファイルにできない。

| 欄 | 中身 |
|---|---|
| `estimated` | いつも `true`（推定） |
| `audio` | パス・sha256・元のサンプリング周波数・チャンネル数・長さ |
| `strong` | 強打 `[{t, strength}]`（`--grid` を渡せば `bar`・`beat` も） |
| `onsets` | 帯域差分の打点 `[{t, strength}]`（同じく `bar`・`beat` も） |
| `grid` | 位置に使った格子（ファイル名・sha256・period・拍数・最初の小節の頭）。渡さなければ `null` |
| `settings`・`tools` | 手順の値と補正の値、librosa・numpy・soundfile の版 |

## 光の強さのキー（`mv audio keys`）

打点の記録から、fx-shot の光（`lights[]`）の強さ（`intensity`）のキーを作る。もとの spec は変えず、その光の `intensity` だけを
置き換えた spec を、もとの spec と同じフォルダに書く（既定は `<spec の名前>_keys.json`。素材の相対パスは spec のフォルダから
読むので、ほかのフォルダには書かない）。手で打っていた稲光の明滅を、打点から作るためのもの。`--out` は入力（spec・打点の
記録と、spec が使う素材の base・depth・マスク・音・overlays）と同じファイルにできない（`--force` でも）。

```sh
uv run mv audio keys audio.hits.json --spec spec.json --light lightning --base 0.12
uv run mv fx render spec_keys.json
```

明滅の形は、実制作の本編の描画の台本の稲妻と同じ。

- **使う打点**: `--from`（既定 `strong`）の一覧を時刻の順に見て、`--section A B`（曲の時刻の [A, B) 秒。いくつでも。無ければ
  曲全体）に入り、直前に使った打点から `--min-gap-s` 秒（既定 1.6）より後のものだけを使う。
- **明滅**: 打点 s からの時間 dt が −0.01 秒以上 0.5 秒未満のとき `exp(−14·dt) + 0.5·exp(−40·|dt − 0.12|)`（打点で 1、
  0.12 秒後にもう一度小さく光る）。量はすべての打点の明滅の最大で、1.2 で頭打ち。
- **キー**: ショットのコマ i の時刻 `i / fps`（曲の時刻は start + `i / fps`）で `v = --base + --gain × 量` を出し、前後のコマと
  同じ値のコマは省く。fx はキーの間を直線で補うので、コマの時刻では式のままの値になる。
- **start**（ショットの 0 秒が曲の何秒か）: spec の `audio` が打点の記録と同じ音源（sha256）なら `audio.offset_s`。違えば
  `--start` が要る。
- 実制作には無い選び方: `--min-strength`（弱い打点を外す）、`--by-strength`（打点ごとに強さを掛けてから最大を取る）。
- 光には作り方の記録 `x_audio_keys`（打点の記録のファイル名と sha256・選び方・start・使った打点の曲の時刻）を付ける。
  値が 20（fx の光の強さの上限）を超えるなら止める。

hooks の中で量を使うとき（fx-timeline の稲妻の部品に渡すなど）は、`mv_pipeline.audio.keys` の `select`（使う打点）と
`amount`（曲の時刻の量）をそのまま呼べる。

## 実制作との比較

- **探し方**: 実制作の拍の格子の台本（一定テンポの格子の総当たり）を、ある曲（4 分弱）でいまの環境のまま動かした結果と、
  `mv audio grid --bpm-min 88 --bpm-max 91` の結果が、bpm・1 拍の長さ・位相・343 拍と 86 小節の時刻・小節の頭の位相・点数・ずれの
  数（合致 285/343、平均 −3.6 ms、標準偏差 22.2 ms、区間ごと −3.3／−2.2／−6.3 ms）まで同じだった。
  - その曲の当時の記録（拍の格子のファイル。丸めた値）とも、bpm・1 拍の長さ・位相・拍と小節の頭の時刻・位相が丸めた桁で同じだった。
  - 細かい探索は置き換わらなかった（実制作でも同じ）。時間は実制作の台本 14.5 秒、`mv audio grid` 7 秒。
  - 点数の和（float32 で順に足す）と探し方は、台本をそのまま写した関数と、合成の入力で値まで同じになることをテストで確かめている。
- **縦の Shorts の曲**（実制作は 174.000 BPM・拍 0 が 0.0200 秒・小節の頭が 2 拍目の 0.3648 秒と決めた。決め方はテンポ・位相・
  和声の変化の確かめを合わせた判断で、1 つの手順ではない）:

  | 方法 | bpm | 位相 | 小節の頭 | ずれ（平均・標準偏差・3 区間） |
  |---|---|---|---|---|
  | 探す（既定） | 173.96 | 0.000 秒 | 1 拍目（`onset`） | +2.7・16.9 ms、+11.9／+6.2／−10.4 ms |
  | 探す（`--fair-refine --downbeat chroma`） | 173.992 | 0.018 秒 | 2 拍目 0.3628 秒（3 区間とも） | +8.1・14.4 ms、+4.7／+10.6／+9.0 ms |
  | 決めた格子（`--bpm 174 --phase 0.02 --downbeat chroma`） | 174 | 0.020 秒 | 2 拍目 0.3648 秒（3 区間とも） | +11.6・15.1 ms、+5.3／+14.3／+15.1 ms |

  - 既定の探し方は粗い探索の刻み（0.02 BPM・0.01 秒）のままで、区間ごとのずれが流れる。`--fair-refine` で決めた値に近づいた。
  - 小節の頭は、`onset` では 1 拍目、`chroma` では決めた値と同じ 2 拍目だった。
  - `chroma` の 8 分の番号ごとの値は、実制作の小節の頭の確かめの記録（同じ格子・8 つの時間の窓）と、8 つの窓とも選んだ番号と
    その時刻が同じで、値は 7 つの窓で小数 3 桁まで同じ、1 つの窓で 2 つの値が 3 桁目で 0.001 違った（計算の環境の差と見ている）。
- **打点**（同じ縦の Shorts の曲、247 秒）: 実制作の縦の Shorts の格子の台本（強打と帯域差分の打点）を、いまの環境でそのまま
  動かした出力と、当時の出力の両方と比べた。
  - 強打 285 個は、台本と同じ 4 桁に丸めて、どちらとも同じ。
  - 帯域差分の打点 1,464 個は、台本と同じ桁（時刻と強さを 3 桁）に丸めて、いまの環境の台本とすべて同じ。当時の出力とは、強さの
    2 つが 3 桁目で 0.001 違った（いまの環境の台本も同じ 2 つが違うので、計算の環境の差）。
  - 小節と拍の位置は、台本と同じく最初の小節の頭を 0.3648 秒に丸めた格子で、1,464 個すべて同じ。`mv audio grid --bpm 174
    --phase 0.02` の記録（最初の小節の頭 0.364827… 秒）のままでは、12 個の拍が 2 桁目で 0.01 違った。
  - 強打・打点の手順と位置の式は、台本をそのまま写した関数と、合成のクリックで値まで同じになることをテストで確かめている
    （22050 Hz と 44100 Hz の音）。
- **強打**（別の縦の Shorts の曲、197 秒）: その曲の解析の記録（強打の時刻を、補正せず丸めずに残している）と、
  `--strong-shift-ms 0` の強打 208 個が浮動小数点の値まで同じだった。
- **光の強さのキー**: 実制作の本編の描画の台本から、稲妻の打点の選び方と量の関数をそのまま取り出し、実際の強打の一覧（上の 2 曲）と
  3 通りの区間で全コマを比べた（24 fps と 30 fps、4,716〜7,411 コマ）。使う打点はすべて同じで、量は全コマで値まで同じだった。
  キーを fx の補間でコマの時刻に読み戻した値との差は、最大 2.8e-17。
- **手で打ったキーとの比べ**: 手で稲光の光のキーを打った 1 ショット（5.4 秒）の音で調べた。
  - 手のキーの 5 つの光のうち 3 つ（2.42・4.66・4.93 秒）は、帯域差分の打点（強さ 0.49・1.06・0.50）と 6 ms 以内だった。
    残りの 2 つ（0.88・1.12 秒）の近くには打点がなかった。
  - 強打（既定の選び方）からは、1.35 秒と 3.65 秒の 2 回だけ光るキーになり、手のキーとは違う。強打の選び方のしきい値は
    調べた音の全体から決まるので、ショットの音だけでなく曲の全体から作れば変わる。

## 入れていないもの

- テンポが変わる曲の格子（区間ごとの格子）、拍の格子の位置の補正（立ち上がりの検出の偏りの較正）。
- 曲の区間の境目（和声と音色の似かよりでまとめる）と、1 秒ごとの音量（実制作の解析の台本の残りの部分）。
- 小節ごとの特徴の表（音量・低中高の帯・立ち上がりの数・調波と打楽器の比・歌らしさ・新しさ）と、カットの時刻の候補の表
