### Design Decisions

- **色の読み方は環境で違う**: Windows の OpenCV 5.0.0 は BT.709 の動画を BT.601 で読む（実測）。Linux の CI の OpenCV は正しく読む（CI のログで確認）。タグが bt709 の動画は ffmpeg で読むようにした。最初のテストは Windows の挙動を前提にしていて CI で落ちたので外した。
- **3D の試作はリポジトリに入れない**: 作品固有の値が多く、試作の段階なので、スクリプトは Git の外に置く。部品にする価値が見えたら改めて判断する。
- **合否の基準はデータを見る前に固定する**: モデルの判定基準は先に書き、文言を変えない。絵の判定はユーザーが行う。
- **AI 生成のモデルは 1 枚のメッシュ**: 髪・服・体がつながっている。自動リグの重みのままでは踊れず、髪、スカート、胸の帯、UV の継ぎ目の二重頂点を直した。
- **顔は Tripo の形を残して立ち絵を投影する**: 面を強くなめらかにする方法は正面はきれいでも鼻とあごが消えた。ユーザーが「横顔がつぶれている」と指摘して分かった。肌の形を残し、前髪で隠れた目のまわりだけをつなぐ方法に変えた。
- **頭は硬い塊として動かす**: 自動リグはあごを頭の骨に 63% しか付けていなかった（実測）。あごより上を頭の骨だけにして、顔の歪みを 12 mm から 0 mm にした（実測、頭に対する動き）。
- **確認の仕方**: 3 コマだけの確認では、ひねるコマの破れを見落とした。全コマを測ることと、色なしで横から見ることを手順に入れる。

### Design Decisions

- **基準は先に固定し、判定はユーザー**: T1〜T5 を描く前に書いた。最後は T を一つずつではなく、第 6 版全体として採用された。
- **体積保持の変形は使わない**: 膝と袖が悪くなった（目視）。普通の重みづけのままにし、肘の袖は袖口の骨で輪ごと回した。
- **動きの写しの癖**: 前腕が自分の軸まわりに半回転し、手がそれを打ち消していた（肘と手首で最大 179 度、合計は 43 度以下。実測）。手の向きは変えずに半分ずつに分けた。合計は -180〜180 度に戻してから半分にする。
- **顔は塗りで直し、形は動かさない**（Session 1 の教訓の続き）。前髪を守るには、目のまわりで一番大きくつながる面だけを塗る。距離だけで判定すると、肌に近い前髪の束まで塗った。
- **当たりは点ではなく面で測る**: 揺れの鎖の節が外にあっても、節の間の帯の面は太ももに入っていた。最初の測り方は近い点が 4 cm 以内のときしか数えておらず、奥まで入った点を見落とした。光線を何方向かに飛ばし、交わる回数の奇数・偶数で中か外かを決めるようにした。
- **Blender の Shrinkwrap（Outside）は使えなかった**: 中か外かを一番近い面の向きで決めるので、口の開いた筒や、ふさいだ口のふちの近くで読み違え、脚から離れた帯まで引き寄せた。描く直前に Python で、閉じた写しに対して上の方法で中の点を外へ出し、骨で動かす前の形の差に直してシェイプキーに書く方法にした。
- **当たりの押し出しを速さに入れない**: 入れると弾んで、帯が上へはね上がって裏返り、暗い裏面が切れ端のように見えた。
- **ユーザーが名指したコマの範囲は 1 コマずつ見る**: 3 コマおきの確認では見落とした。スマホの写真は、動画の範囲を切り出して全コマと比べると、どのコマか特定できた。
