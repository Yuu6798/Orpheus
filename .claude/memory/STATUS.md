## Phase

ロードマップ（`docs/roadmap.md`）の段階 0（安全網と演出エンジン fx v0.1、PR #2・#6）に続き、段階 1 を公開済みの第 1 作の 1 カットで実施し、ユーザーが both 版を採用した（2026-10-30 に PC で `fx accept` を記録済み）。段階 1 の課題だった色調整・周辺減光・粒状感は fx の `look` として PR #9 で足し、2026-10-30 に段階 2 の Part A として、段階 1 のカットに公開版の調色（`grade_keys` 11 キー）と既定の減光・粒を当てた 4 版を描いて公開版と並べた（全版 technical_pass、ユーザーの判定待ち）。判定の後、ユーザーの了承で Part B（同じ作品の別カットに設定変更だけで当てる）に進む。PC は Windows のスマート アプリ コントロールが有効なため、.venv を署名つき Python で作ってある（手順は `docs/dependencies.md`）。2026-10-31 にユーザーの資料をもとに、ダンス合成 `mv dance`（PR #11）と、書き出し前の機械的な検査と行・秒の確認表 `mv gate`（PR #12。AGENTS.md の裁定の例外としてユーザーが承認）を足し、続けて設定を `dance-shot/0.2` に広げた（PR #14〜#18）。ユーザーの素材で縦のダンス動画を 3 本作り（コードの変更なし）、見つかった色の読み違いを PR #21 で直した。2026-11-01〜02 にリポジトリの外で進めた、動画から推定した動きを 3D キャラに載せる試作は、ユーザーの三面図でモデルを作り直し、第 6 版をユーザーが採用して終えた（DANCE-3D-1）。2026-11-03 に自作 3D ツール `tools/model3d` を直して広げた（PR #22〜#30）。2026-11-05 に、制作の計画と証跡 `mv workflow`（PR #31）と、描画の失敗時の診断（PR #32）が入った。2026-11-06 に、リポジトリの外でその 3D モデルの 32 秒を描き終えた（DANCE-3D-3）。同じ日にユーザーが Orpheus を「画像 → 2D 動画 → 3D 初期モデル → 3D 動画」を作る道具箱と決め、実制作ツールの取り込みを判断した。細部はユーザーの委任で、その方向に沿って決めた（統合。`docs/roadmap.md` の「ツールキットの計画」と「判断（2026-11-06）」）。段 0（TOOLKIT-0）は #33〜#37 で済み、LICENSE は Apache-2.0 に決めた（DECIDE-1 を閉じた）。次は段 1（TOOLKIT-1）。並行トラック（工程の骨格の実害修正）は未着手。2026-11-07 にユーザーの依頼で、生成動画の検品 `mv inspect`（異常の位置・分類・設定画との照合・時系列の検査・VLM の受け渡し・修正計画）を足した（AGENTS.md の裁定の例外。`docs/inspect.md`）。同じ日に実素材（生成 AI の緑背景のダンス動画 2 本・i2v 2 本）で一度通し、設定画の向き違いで出た衣装の誤検出を直して、設定画の名前・切り抜きの画像・VLM の指摘の文を報告に出した（しきい値は変えていない）。続けて、修正計画で直して検品し直す流れ・実素材にわざと入れた異常（7 つ全部検出）・30〜60 秒の速さとメモリ・透過と緑背景の設定画・実際の API での VLM（3 回。14 コマで約 $0.09）・3D 描画を試し、見つかった手当ての規則・静止画のメモリ・VLM のキャッシュとトークン数の記録・緑抜きの注意を直した（#55）。同じ日に Windows の PC と Blender 4.5.15 の描画でも通し（INSPECT-6）、`render.stage` に緑背景と透けの `background` を足し、Blender の描画にわざと入れた離れた塊の見落とし（数える塊の大きさをいちばん大きい塊の 2% → 1% に）と、人物が戻ったコマの動きの急変の誤検出を直した。
