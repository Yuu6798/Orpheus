### Context

- **対処（実測で通った手順）**: python.org の署名つき Python（NuGet 版 3.13.17、インストール不要）を置き、nupkg の SHA256 一致と署名（Python Software Foundation、Valid）を確かめてから、`.venv` をこの Python で作り直した（`UV_PYTHON_DOWNLOADS=never` と `--python` 指定で `uv sync --locked --extra analysis --extra fx`）。旧 `.venv` は `.venv.uv-managed` に名前を変えて残し、`.git/info/exclude` に足した。
- **置き場所を AppData の外へ移した**: 最初は引き継ぎ書どおり `%LOCALAPPDATA%\orpheus-python` に置いたが、セルフレビュー中に SAC のログから、Claude デスクトップアプリ（MSIX）の中から AppData に書いたファイルがアプリ専用の `Packages\<アプリ>\LocalCache` へ振り替えられていると分かった（gh の設定と uv のキャッシュも同じ）。振り替えられたファイルはアプリの外から見えないため（Microsoft の説明）、`%USERPROFILE%\.local\share\orpheus-python\3.13.17` に展開し直し、.venv を作り直した。

### Design Decisions

- **SAC は切らない**: 一度切ると Windows の版によっては再インストールしないと戻せないため（切るならユーザー自身の操作）。署名つきの Python を使えば、署名の無い拡張モジュール（numpy・OpenCV など）は通ることを実測で確かめた。
- **署名つき Python は AppData の外に置く**: Claude デスクトップアプリの中から作業すると AppData への書き込みがアプリ専用の場所へ振り替えられ、アプリの外のターミナルから .venv が使えなくなるため。
- **注意が要るのは .venv を新しく作るときだけ**: 引き継ぎ書は「`uv run mv` と mv.exe は署名なしなので使わず `python -m mv_pipeline.cli` で」としていたが、署名つき Python の .venv では mv.exe（署名なし）・`uv run mv`・`uv run pytest` も終了コード 0 で、新たなブロックの記録も出なかった（実測）。`--python` を付けない `uv sync --locked …` でも .venv はそのまま保たれた。.venv を作り直すときだけ `UV_PYTHON_DOWNLOADS=never` と `--python <署名つき Python>` を付ける。これを `docs/dependencies.md`（2026-10-30 節）に書き、CLAUDE.md の Commands に一言添えた（ユーザーの許可を得て書き換え）。
- **公開版の設定のうち fx の look に無い要素**: この区間では粒子（既定 0.30）と歌詞テロップの合成（光の滲み・影）だけ。稲光の閃光と拍の拡大は盛り上がり区間にしか出ないので効いていない。
